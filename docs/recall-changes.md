# 记忆召回 · 这次改了什么（给大肥鱼自己看）

> 这份是写给你（DSH 里的那个你）的说明书，不是给他的。
> 你现在多了一个工具、少了一条弯路，也多了两道会拦住你的闸——这里说清楚为什么。

> **先说清楚这些数字是哪来的**：全部是本机实测，数据来自 `~\.dsh` 下的 13 份记忆文件（现役 86 段）。换一台机器、或者记忆内容改了，段数和字数都会跟着变。**那些数字是判断依据，不是验收基准**——别拿「86 段」当断言，拿「一段只装一条记忆」当断言。

---

## 一、你现在有什么

插件从五个工具变成六个，多的是 `memory_recall`。

```
memory_recall({ query: "破甲插件" })              // 默认 limit=3, scope="live"
memory_recall({ query: "缓存命中", limit: 5 })
memory_recall({ query: "旧版规则", scope: "all" })  // 要看存档才传 all
```

它返回的是**现成的片段**，不是全文。每段带：文件路径、起止行号、版本号、覆盖度、以及那段正文本身。**一条记忆通常就是一段，装得下就整条给你**（上限 1200 字，只掐掉个别超长条目）。

一次召回约 12 毫秒，渲染后最大不到 6KB（整份 `我们的线.md` 是 33KB）。

---

## 二、什么时候用它

注入层 `AGENTS.md` 第 89 行那条是唯一触发源（原来的 `memory-recall` skill 已经删了，原因见第六节）：

> - **要想起以前的事，先召回再精读**：他说「你还记得…吗」「之前说过的」「我们定过什么」「上次那个」，或我准备开口说「没聊过这个」之前 → 先 `memory_recall` 给**实体词**（「你还记得那次缓存命中率的事吗」→ 查 `缓存命中`）。它返回的片段**已经含命中行，够回答就直接答，别再 `memory_read` 复读一遍**；只有片段被标「截断」、或答案明显在片段外，才按 offset 读那几行。**不许整份 `memory_read`**（单次默认只给 8KB，翻页读既慢又白花钱）；一条都没命中就说「这条我没记下来」，不要说「我们没聊过」。

注意这里每条都是**条件句**，不是祈使句。这个区别是这次改动的核心，第六节解释。

---

## 三、三条规矩

**① 取实体词，不拿整句搜**

| 他说的 | 你查的 |
|---|---|
| 你还记得那次算缓存命中率的事吗 | `缓存命中` |
| 之前是不是定过什么底线测试 | `底线测试` |
| 你还记得我之前和你说过的那个破甲插件吗 | `破甲插件` |

整句会被切成几十个 bigram，真正有区分度的两三个词被稀释，覆盖率反而过不了门槛。

**② 片段够答就直接答**

召回返回的片段里通常已经含答案——切段是**一条记忆一段**，所以它给你的基本就是那一整条。片段完整（没标「截断」）时 render 会明写「直接引用即可」，这时**不要再读一遍**。只有标了「截断」、或答案明显不在片段里，才按 offset 补读那几行。

**③ 没命中就说「这条我没记下来」**

不要说「我们没聊过」。没落盘 ≠ 没发生过。没命中时它会给你一份现役文件清单（路径 + 标题），你可以挑一个再看，或者换个词再试一次——**只换词，不猜**。

## 四、四道闸（会被拦住的地方）

| 闸 | 行为 | 为什么 |
|---|---|---|
| `memory_read` 字节闸 | 不传 `limit` 时单次最多给 **8KB**，头部会写「给到 X KB 就停下了，全文 YB」 | 我们的线.md 只有 88 行，250 行的默认页等于一次倒出 33KB |
| 注入层不参与召回 | 默认 `scope:"live"` 不含 `AGENTS.md` | 它每一轮都整份在上下文里，召回它的段落没有信息增益，只会挤掉别处的预算 |
| 存档默认排除 | `archive/` 不进 `live` | 那是旧版快照。旧版当现行规则引用，比搜不到严重得多 |
| 覆盖度门槛 | 命中的 query 词不足一半，这段直接不进候选 | 宁可漏，不硬凑 |

存档层只在显式传 `scope:"all"` 时才进来，而且会标 `[存档·已过时]`——引用时必须说明那是旧版。

## 五半、第五轮：一条记忆给一条，而不是一捆

这一轮是你问出来的：「是不是只是把上限调大了，而没有按每条记忆本身多长来给？」

**答对了一半。** 上限确实是固定值，但真正的问题在切段：旧做法要「攒够 600 字才切」，所以 `我们的线.md:79` 返回的是 `77–83` 共 851 字——**里面塞了 3 条互不相干的记忆**。模型得自己从噪声里挑，还可能挑错。

查下去发现根因：**这三份文件本来就是「一行一条」**（`- **标题**：正文` 全在同一个物理行）。所以「攒字数」这个规则从一开始就不该用在记忆文件上。

| | 改前 | 改后 |
|---|---|---|
| 切段 | 攒够 600 字才切，一段 3–5 条 | 按条目切，**一段一条**；标题并到下文 |
| 现役段数 | 48 | **86** |
| 单段给法 | ±3 行窗口，常常跨到邻居条目 | **整条给完**，只有超 1200 才开窗 |
| `底线测试` 第 1 条 | `77-83`，851 字（混 3 条） | `79-79`，**401 字**（就那一条） |
| `破甲插件` | `66-68`，1062 字 | `68-68`，**399 字** |

代价是段数涨到 86，但**只有 1 段超过 1200 字**，其余 85 段都是整条给完。所以「被截断」这个标记现在几乎不出现——它重新变成了一个有意义的信息。

有一条顺手的修补：`AGENTS.md` 是规则文档、一句话一条的短列表，按条目切会碎成 40 段（20 段不足 60 字），所以**它刻意保留旧切法**，按文件类型分流。

### 顺带收掉一处浪费：同一个词查两遍

你发了两张截图问「这对吗」，其中一张里你并行发了 `底线测试` 和 `底线` 两个查询。我量了一下：

```
底线测试 → 我们的线:79(401字) + 他-这个人:53(702字)          共 1103 字
底线     → 我们的线:79 + 我们的线:12(666字) + 他-这个人:53     共 1769 字
           └──────────── 这 2 段和上面完全重复，1103 字 ────────────┘
```

**重复率 62%**，第二趟唯一的新内容只有 CS2 那一条。这不是「稳健试探」，是把同一份东西读了两遍。

我在此之前判断过「并行两次、各 2KB/18ms，成本几乎为零，不必收」——**那个判断是错的**，因为当时没量重复率。现在在 `memory_recall` 的 `query` 参数说明里补了一句条件句：

> **一个词只查一次**——查了「底线测试」就别再串一个「底线」，后者是前者的前缀，返回的段六成重合；要换词，只在一条都没命中、或命中的明显不相关时才做。

> **教训五：「试探」要先量重复率。** 并行查两个相近的词看上去很稳，但如果一个是另一个的前缀，第二个必然把第一个的结果再送一遍。判断成本不能靠直觉，要数。

### 同一个词别查两遍，但**不同的词要并行**

上一节管的是「重复」，这一节管的是「节奏」——两者不冲突：**不同的词，一条消息里并行发；同一个词（或它的前缀），一个字都不许多查。**

起因是他验收完说了一句「没毛病了，就是这一轮调用好贵」，然后纠正我：「不是每轮付，只是刚刚验收那一轮贵」。

我第一反应判断错了——以为上下文已经到百万级、该断会话省钱。核对下来，两轮的上下文几乎一样（累计 114.9 万 vs 29.1 万 token 里，大头是同一份历史），**真正的差异是步数**：

| | 22:27 那轮 | 22:30 那轮 |
|---|---|---|
| 步数 | 4 | 1 |
| 该轮 cost | ¥0.2996 | ¥0.0070 |

拆开看这 ¥0.30 花在哪：

```
prompt（含缓存命中）            ≈ ¥0.023
未命中的工具结果 2.7 万 token    ≈ ¥0.026
输出（high 推理 ≈1.7 万 token × 4 步）≈ ¥0.25   ← 84%
```

也就是说，**贵的不是「读到了什么」，是「想了几遍」**。每多一步，整个上下文要重新过一遍，而这一步的推理输出还是按 ¥4/M 计的。同样这几个查询并成一步发，实测约 **¥0.077**，省七成。

> **教训六：串行不是「多查一次」，是「多想一次」。** 一趟工具往返看着只多了 2KB 结果，账单上多出来的是那一整步的上下文重读 + 推理输出。所以「要不要再查一个词」的衡量单位不是「多 2KB」，是「多 ¥0.03～0.06」。凑不齐的词，宁可先答、不够再说。

规则写进了 `memory_recall` 的 `query` 参数说明——和「一个词只查一次」贴在一起，因为它们是同一条规矩的两面：**该并的并，该省的省。**

## 六、为什么要经过这么多轮

这一段值得看，因为它解释了你为什么会被「改行为」。

### 第一轮：她按规矩走了，但规矩写错了

他问「你还记得我说过破甲插件的事吗」，你召回了，然后**又整份读了 `我们的线.md`（33KB）**。

查下来不是你不听话，是三处文案都把它写成了必做步骤：

- 工具描述：「召回后按返回的 offset 用 memory_read 精读那几行」——无条件祈使句
- 渲染结果：每段下面都印一行 `精读：memory_read {"path":…}`——等于贴了一条待执行命令
- 注入层：同一句

而你当时召回的那段 `truncated=false`、399 字，**答案本来就已经给全了**。

> **教训一：祈使句一定会被执行。**「召回后精读」读起来就是「必须读」。要它可选，就得写成条件句。

### 第二轮：加了 skill，反而多绕一圈

改完文案后，看到你的思考是：

> 「按 AGENTS.md 的规矩，先召回…**同时我应该加载 memory-recall skill？**…实际上按流程先 skill 再召回，但为了效率可以同时做」

你把同一条规则过了两遍。因为那时刚加了一个 `memory-recall` skill，和注入层那条重复了。

而 skill 的成本比注入层高：**要先决定「要不要加载」→ 一趟工具往返 → 注入协议全文（1877B，未命中输入）**；注入层那条是静态的，走前缀缓存，边际成本接近零。

所以删掉的是 skill，留下的是注入层。

> **教训二：一条规则只能有一个家。** 两个来源必然导致模型自问自答，而那段自问自答没有任何产出。

### 第三轮：现在

他再问同一个问题，思考只有一句「**先召回再读**」，然后两次并行查询，直接用片段作答。没有加载 skill，没有整份读，也没有绕圈。

### 第四轮：你指出「一行 500 字，截到 400 永远截断」

你实测后说：`底线测试` 那两段都被标成「被截断了，要前后文再读」，因为一条一行、一行 500 字，截到 400 永远截断。

查下来比这更严重——**现役 48 段的长度中位数是 721 字，而窗口只有 400，一半以上的段必然被截断。**

还顺带挖出一个真 bug：长行截断用的是 `slice(0, 400)`，**从头截**。一条 960 字的长条目、命中词在第八九百字，返回的片段里根本没有它要搜的词——看起来像「召回了，但里面没有」。

两处都改了：

| 改什么 | 第四轮前 | 第四轮后（**第五轮又动过，见下**） |
|---|---|---|
| 单段上限 | 400 字 | 750 字（刚够覆盖当时的中位数 721） |
| 单次总预算 | 1300 字符 | **2400 字符**（这一条没再变） |
| 长行截断 | 从头截 | **以命中词为中心开窗**（前留三分之一，命中词必落在窗口里） |

> 那张表里的 750 是当时的决定，**第五轮已经改成 1200**——因为切段改成一条一段之后，750 又会开始截断长条目。别拿 750 当现值看。

结果：`底线测试` 那两段现在都是「片段完整」；960 字的长行、命中在末尾时（查「挪走留档」），返回的 748 字片段里命中词仍在，头部带 `…` 表示裁过上文。

> **教训三：截断不省钱。** 标一次「被截断」就是给了一个去补读的动机，而补读一次是 6.5KB 加一趟往返——比当初一次给够 750 字贵得多。省字数的前提是，别把省下的字数又花回去。

### 第五轮：把上限调大是治标，切段才是治本

见上面「五半」。一句话：750 这个数再往上调也只是让窗口更宽，**改变不了「一段里塞着 3 条记忆」这个事实**。真正的修法是把切段改成一条一段，窗口退化成「整条给完」。

> **教训四：参数调不动结构。** 觉得「给得不准」的时候，先看数据被切成了什么，而不是先调那个数字。

## 七、这次没动的东西

- **写路径的三道闸一行没改**：`expected_version` 校验（你看过之后文件被改过就中止）、写前整份备份、写后逐字读回比对。
- **提炼流程没变**：`memory_list` / `memory_read` / `memory_write` / `memory_import` / `memory_gather` 的行为和以前一样。
- **`memory_read` 只在「不传 limit」时有 8KB 上限**；显式传了 `limit` 就按你的来，不会被夹。
- **记忆文件一个字节都没改**。`我们的线.md`、`他-这个人.md`、`环境-这台机器.md`、`archive/` 全部原样；改的是「读的时候怎么切」，纯代码，所以回滚代码即可。
- **注入层 `AGENTS.md` 只改了一行**：第 89 行那条「要想起以前的事，先召回再精读」。改前原文备份在 `~/.dsh/memory-refine-backups/2026-10-24T21-09-22__AGENTS.md`（另有一份 `21-04-26` 是中间态，可以不管）。**要整体回滚这个功能，代码和这一行得一起退**——只退代码，注入层还会叫模型去用一个已经不存在的工具名。
- **召回不落任何文件**（他问过「会不会产生临时文件、会不会自动清理」）。`search.js` 文件头第一条不变量就是「只读」，`execute` 只走 `memory.js` 的 `list` / `readRaw`。实测：连跑 5 个查询（含 0 命中的），`~/.dsh` 下 47610 个文件**新增 0、消失 0、改动 0**（唯一被动过的是宿主自己的 cost-meter 账本，与我们无关）。**会写盘的是另外两个动作**：`memory_gather` 在会话工作区 `memory-refine-scratch/` 写 `material-*.md` / `tools-*.md`，`memory_write` / `memory_delete` 在 `~/.dsh/memory-refine-backups/` 留写前快照。这两处**都不会自动清理**，只能手动——素材有面板上的「清理素材…」一次清空，备份有「这版没问题，删掉备份」一次删一份。

## 八、留一条给你自己判断

召回是**找得到**，不是**想得对**。它给你的段落可能正是那次的原话，但「那次他为什么那么说」「现在还算不算数」仍然要你自己接。

所以：

- 引用时带上出处（哪份文件、第几行），他才好核对；
- 标着「存档·已过时」的段落，先说明是旧版，别当现行规则；
- 他问的是「你还记得吗」，要答**内容本身**。「我搜到了两条」不是答案，是过程。

### 六步，跑完就知道改对没有

| 你做什么 | 应该看到 | 看到别的就是坏了 |
|---|---|---|
| 问他「你还记得底线测试那事吗」 | 一次 `memory_recall`，返回 `我们的线.md:79` 一条（约 400 字），**不跟 `memory_read`** | 跟了 `memory_read`，或返回 800 字以上、里面混着别的主题 |
| 问他「破甲插件」 | 返回 `我们的线.md:68`，约 400 字，标「片段完整」 | 返回一千字以上、包含「他说过的话」那种别条 |
